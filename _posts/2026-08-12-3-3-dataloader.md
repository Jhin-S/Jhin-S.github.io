## 1. Dataset Splitting with `random_split` (`random_split`을 활용한 데이터셋 분할)

**[KR]**
* **3-way 데이터 분할 목적 (3-Way Data Split Purpose):**
  * **학습 세트 (Train Set):** 모델이 가중치를 학습하는 데 사용합니다.
  * **검증 세트 (Validation Set):** 학습 과정에서 하이퍼파라미터를 튜닝하고 과적합(Over-fitting)을 감지하는 데 사용합니다.
  * **평가 세트 (Test Set):** 학습 완료 후 모델의 최종 일반화 성능(generalization performance)을 딱 한 번 평가하는 데 사용합니다.

**[EN]**
* **3-Way Data Split Purpose:**
  * **Train Set:** Used by model to learn weights.
  * **Validation Set:** Used during training to tune hyper-parameters and detect over-fitting.
  * **Test Set:** Used strictly once after training completion to evaluate final generalization performance.

### 구현 코드 (Implementation Code)

```python
import torch 
from torch.utils.data import random_split 

total_size = len(full_dataset) 
train_size = int(0.70 * total_size) 
val_size = int(0.15 * total_size) 
test_size = total_size - train_size - val_size # 반올림 연산 오차 방지

train_dataset, val_dataset, test_dataset = random_split( 
    full_dataset, [train_size, val_size, test_size] 
) 
```

## 2. Batching & Shuffling Mechanics (배치 연산 및 셔플링 메커니즘)

**[KR]**
* **배치 계산 예시 (Batch Calculation Example):**
  * 전체 학습 샘플: $5732$ (배치 크기: $32$)
  * 전체 배치 개수: $5732 / 32 = 180$개의 배치
  * $32$개로 꽉 채워진 $179$개의 완전한 배치 + $4$개로 구성된 $1$개의 나머지 배치(Remainder batch)

**[EN]**
* **Batch Calculation Example:**
  * Total Train Samples: $5732$ (Batch Size: $32$)
  * Total Batches: $5732 / 32 = 180$ batches
  * $179$ full batches of $32$ samples + $1$ remainder batch of $4$ samples

### DataLoader Setup & Inspection (데이터로더 설정 및 단일 배치 빠른 검증)

```python
from torch.utils.data import DataLoader 

train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True) 
val_loader = DataLoader(val_dataset, batch_size=32, shuffle=False) 
test_loader = DataLoader(test_dataset, batch_size=32, shuffle=False) 

# 전체 반복문 없이 단일 배치 데이터 추출 (Quick Batch Inspection)
images_batch, labels_batch = next(iter(train_loader)) 
print(images_batch.shape) 
print(labels_batch.shape) 

# 출력 (Out): torch.Size([32, 3, 224, 224])
```

## 3. Performance Critical Anti-Patterns (성능 관련 치명적 실수)

**[KR]**
* **안티패턴 1: `__getitem__` 내부에서 무거운 파일 I/O 실행 (Heavy File I/O inside `__getitem__`):**
  * **잘못된 방식 (Bad):** `__getitem__` 안에서 매번 CSV나 메타데이터 파일을 다시 읽어오는 경우 (Reloading CSV/Metadata).
  * **치명적 영향 (Impact):** 파일 읽기 연산이 $5732 \times \text{에포크 수}$ 만큼 실행되어 극심한 파이프라인 병목 현상이 발생합니다.
  * **해결책 (Fix):** 메타데이터 로딩과 파싱은 오직 `__init__()` 내부에서 한 번만 실행합니다.
* **안티패턴 2: VRAM 용량 초과 방치 (Ignored VRAM Limits):**
  * **치명적 영향 (Impact):** `Runtime Error: CUDA out of Memory` 발생.
  * **해결책 (Fix):** 배치 크기를 축소합니다 (예: $64 \rightarrow 32 \rightarrow 16$).

**[EN]**
* **Anti-Pattern 1: Heavy File I/O inside `__getitem__`:**
  * **Bad:** Reloading CSV/Metadata inside `__getitem__`.
  * **Impact:** Executes file load $5732 \times \text{Epochs}$ times, causing severe pipeline bottleneck.
  * **Fix:** Load and parse metadata once inside `__init__()`.
* **Anti-Pattern 2: Ignored VRAM Limits:**
  * **Impact:** `Runtime Error: CUDA out of Memory`.
  * **Fix:** Reduce batch size (e.g., $64 \rightarrow 32 \rightarrow 16$).
